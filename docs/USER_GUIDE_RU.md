# uTempGuard — руководство пользователя

[Главная](../README.md) · [Установка](INSTALL_RU.md) · [English](USER_GUIDE_EN.md)

## Запуск и управление

- **`00_START-HERE.cmd`** — первое знакомство: первоначальная настройка либо открытие большого главного окна. Также можно дважды щёлкнуть **`Open-uTempGuard.cmd`** или по значку возле часов.
- **`Start-uTempGuard.cmd`** — запустить уже настроенный монитор и открыть его главное окно. Кнопка закрытия большого окна только скрывает его — монитор остаётся активен.
- **`Управление.cmd`** — текстовое меню: статус, запуск/остановка, диагностика, автозапуск.
- **Значок в трее** — двойной щелчок открывает большую главную панель; правая кнопка открывает компактное тёмное меню. Во вложенных страницах используйте стрелку в шапке или Esc.
- **`Open-Icon-Gallery.cmd`** — посмотреть все 28 SVG и анимацию без реального нагрева. [Каталог прямо на GitHub](ICON_CATALOG.md) показывает все рисунки даже без запуска HTML.

## Что означают показания

Главный индикатор отображает максимальную достоверную температуру из датчиков, выбранных для **«Показывать»**. В меню раздельно задаются:
1. **Показывать** — какие температуры выводить на экран / иконку: всё AIDA64, ядра, ядра+ЦП, ядра+ЦП+Package или собственный набор галочками.
2. **Выключение** — по каким датчикам оценивается аварийный порог. Это **отдельный выбор**, требующий отдельного разрешения.
3. **Внешний вид** — компактный/полный стиль, шрифт, фон, прозрачность, размещение, показ индикатора, галерея.
4. **Язык** — Русский / English, сохраняется локально в `%LOCALAPPDATA%\uTempGuard\language.json`.
5. **Обновления** — проверка/установка новой версии через Git для клона, ссылки на релизы и документацию. Для ZIP используется ручное обновление.

При отсутствии свежих достоверных показаний программа сообщает об ошибке датчиков и блокирует защитные действия, а не подставляет старую температуру.

## Официальные температурные SVG

Векторные оригиналы: `assets/logo/utg_w_*.svg` для тёмной панели задач и `assets/logo/utg_b_*.svg` для светлой. Каждые 10°C меняется диапазон 000…100; начиная с 80°C, если Windows продолжает работать, ordinary/active чередуются каждые **400 мс**. Это декоративная реакция значка, не доказательство работы защиты.

Чтобы увидеть все состояния, откройте `docs/icon-gallery.html` в браузере или команду `Open-Icon-Gallery.cmd`. Выберите тему, ползунком температуру, размер 32px, включите демонстрацию анимации. Реальная температура процессора не меняется.

Если исправляете исходный SVG в CorelDRAW, сохраняйте тот же номер и имя. GitHub Actions сможет снова получить соответствующий 64px PNG-ресурс при следующей публикации. Исходные CDR — пользовательские рабочие файлы; без отдельного разрешения их нельзя автоматически удалять, переносить или публиковать.

## Состояние защиты и пороги

**Новая установка = Observe**, только наблюдение. В существующей пользовательской конфигурации предупреждение настроено на 70°C, аварийный порог — 75°C. Это значения **конкретной настройки**, а не стандартные безопасные нормы для всех компонентов.

Состояние проверить:

```powershell
.\Emergency-Control.ps1 -Action Status
```

- `MonitorRunning=True` и `RunningMode=Live` означают, что монитор запущен в соответствующем режиме.
- Только одновременно подтверждённые `ForcedShutdownArmed=True` и `ShutdownSourceApproved=True` указывают на разрешённое действие для текущих датчиков. Даже они не обещают срабатывания при зависании ОС/AIDA64.
- `ShutdownSensorMode=All` может включать GPU и диски. Порог 75°C не универсален; выбирайте датчики, понимая особенности компонентов.
- При 70°C программа может запрашивать штатное закрытие лишь **заранее разрешённых** приложений. Если `ApprovedAppCount=0`, никакие программы этой функцией не закрываются.
- При разрешённом аварийном выключении возможна **потеря несохранённых данных**. Не изменяйте режим защиты ради проверки графики.

Включение и отзыв допусков описаны в `Emergency-Control.ps1` и техническом журнале. Не пытайтесь проверять настоящим нагревом до порога.

## Где сохраняются данные

- `config.json` — локальный файл рядом с программой, **не публиковать**.
- `live-approval.json` — локальное разрешение, не входит в ZIP/GitHub.
- `%LOCALAPPDATA%\uTempGuard` — журналы, статусы, внешний вид, язык, датчики и дополнительные разрешения.
- `assets/logo` — оригинальные SVG; `assets/tray-icons` — подготовленные маленькие кадры.
- `docs/icon-gallery.html` — безопасный офлайн-просмотр.

**Не удаляйте папку с работающим монитором, пока не остановили его и не проверили автозапуск.**

## Обновить / остановить / диагностика

Если это **Git-клон**:
```powershell
.\Update-uTempGuard.ps1 -Action Preview
.\Update-uTempGuard.ps1 -Action Apply
.\Manage.ps1 -Action Status
```

Вторая команда потребует `UPDATE`. Для ZIP-версии откройте [Releases](https://github.com/sunpole/uTempGuard/releases/latest) и следуйте [инструкции установки](INSTALL_RU.md#обновление-без-потери-данных).

Если датчики не видны: `Manage.ps1 -Action Diagnose`, проверьте работающую AIDA64, правильный exe, включённый SensorValues и обновление STIME/SDATE. Если AIDA64 запустилась позже uTempGuard при входе в Windows, монитор может некоторое время показывать «Нет данных».

Сообщить о проблеме: [GitHub Issues](https://github.com/sunpole/uTempGuard/issues), желательно без личных данных, серийных номеров, локального `config.json` и `live-approval.json`.
