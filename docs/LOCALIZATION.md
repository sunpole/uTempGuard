# uTempGuard — локализация / Localization

## Цель / Purpose

Для локализации интерфейса используются отдельные UTF-8 JSON-каталоги с одинаковыми ключами:

- i18n/ru-RU.json — русский / Russian (fallback).
- i18n/en-US.json — английский / English.
- src/Guard.Localization.psm1 — загрузка, проверка, выбор языка, локальный конфиг.
- tests/Test-Localization.ps1 — совпадение ключей, параметры шаблонов, сохранение выбора, безопасная обработка повреждённых файлов.

Каталоги устроены по версии схемы: locale, schemaVersion=1, messages — плоский словарь ключей и строк. Локализация НЕ меняет числовые данные, температуры 70/75°C, идентификаторы AIDA64, системные команды или одобрения выключения. В JSON нельзя хранить исполняемый код.

## Что уже локализовано / Current coverage

RU/EN: заголовок и подзаголовок, главная страница компактного меню, настройки «Показывать» и «Выключение», пять режимов, выбор датчиков, страницы показаний, внешний вид (фон, стиль, непрозрачность, шрифт, расположение, видимость), обновления, GitHub, сведения о программе, статусы и пользовательские уведомления мониторинга. Язык меняется во время работы без перезапуска. Выбор хранится ТОЛЬКО локально в %LOCALAPPDATA%\uTempGuard\language.json, а не в config.json и не в GitHub.

Часть резервного старого ContextMenuStrip, служебных диагностических ошибок/старых PowerShell-команд, журнала событий и отдельных Windows MessageBox пока использует исходные фиксированные строки. Это перечислено явно, чтобы не утверждать полный перевод там, где код ещё не переключается на каталог. Идентификаторы внутренних событий и поля JSON не следует переводить — они являются машинным API; тексты ошибок CLI можно локализовать впоследствии, не ломая парсеры.

## Как добавить язык / Add a language

1. Скопировать i18n/en-US.json в i18n/<language>-<COUNTRY>.json (например, i18n/de-DE.json или i18n/fr-FR.json).
2. Изменить поле locale, оставить schemaVersion равным 1 и перевести значения в messages, **не меняя ключи**.
3. Сохранить UTF-8. Плейсхолдеры {0}, {1} должны оставаться такими же и в том же количестве.
4. Добавить новый ключ language.<locale> для названия языка во ВСЕ каталоги (например, language.de-DE = Deutsch). Если его нет, UI использует технический ключ как запасное значение.
5. Запустить tests/Test-Localization.ps1 и tests/Test-ModernMenu.ps1 в Windows PowerShell 5.1. Тесты требовательны к совпадению наборов ключей.
6. После добавления файла валидный язык автоматически появляется на странице «Язык» без изменений исходного PowerShell. Пользователь выбирает его, и затем язык запоминается локально.

Если перевод в выбранном каталоге отсутствует, Get-GuardText использует ru-RU, а если ключ вообще неизвестен — возвращает его имя (видимый диагностический сигнал, чтобы не скрыть ошибку). Неправильный или повреждённый локальный language.json возвращает язык ru-RU и не затрагивает защиту.

## Ключи и интерполяция / Keys and placeholders

- app.*, home.*, nav.*, page.* — шапка и навигация.
- mode.*, option.* — режимы и датчики.
- approval.*, prompt.* — потенциально опасные подтверждения выключения; переводы должны оставаться предупреждающими.
- appearance.* — внешний вид.
- updates.*, about.*, language.* — обновление, сведения, язык.
- notice.*, error.*, state.* — уведомления, ошибки, состояния датчиков.
- fallback.* — ресурсы будущей полной локализации старого меню.

Например: home.temperature = Температура · {0}°C / Temperature · {0}°C. Код передаёт только числовой параметр: Get-GuardText -Key 'home.temperature' -Values @(41). Переводчик не должен вставлять команды, экранировать формат вручную или редактировать PowerShell ради изменения текста.

## Правила UI / UI rules

Главный экран не должен показывать двухстрочные пункты, прокрутку или скрытые команды при обычной рабочей области высотой 720px. Все действия имеют ширину 342px, строку 26px и AutoEllipsis=true. Подробности вынесены на страницы; датчики разбиты по 12 на страницу. При низком разрешении доступна прокрутка только как fallback. RU и EN тестируются одинаково. Логотип остаётся пользовательским SVG, язык его не меняет.

## For maintainers

Safety logic must stay locale-agnostic: Get-GuardDecision, temperature catalogs, consent artifacts and emergency action guards must never branch on current language. Keep locale outside config.json/live-approval.json. Test UI changes in Windows PowerShell 5.1 CI before merge. Prefer short labels in each language; do not rely on text wrapping to show actions.
