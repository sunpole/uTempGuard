# uTempGuard v0.2.0 — независимые источники температуры

Релиз исходного кода для Windows 10/PowerShell 5.1.

## Новое
- Два отдельных раздела в меню: «ПОКАЗЫВАТЬ ЧТО» и «ВЫКЛЮЧАТЬ ПК ПО ТЕМПЕРАТУРЕ».
- В каждом — пять режимов: все температуры AIDA64, максимум ядер, ядра+ЦП, ядра+ЦП+CPU Package, собственный набор датчиков галочками.
- Список доступных AIDA64 датчиков обновляется из подтверждённого экспорта; поддерживаются доступные CPU, GPU, системная плата, накопители и другие температурные каналы AIDA64.
- **Важно:** дополнительные источники Windows/WMI пока не включены, поскольку их корректность для данного компьютера не подтверждена.
- Источник отображения не влияет на аварийное выключение. Новый источник выключения при 75 °C требует отдельного явного подтверждения и свежих данных; без него действия заблокированы.

## Совместимость и ограничения
- При обновлении уже включённого Live сохраняется прежний разрешённый источник CPU Package+ядра. Новые датчики аварийно не включаются автоматически.
- Локальные config.json, live-approval.json и разрешения не публикуются, не перезаписываются обновлением.
- Требуется AIDA64 с включённым экспортом датчиков. Отсутствующие показания не подменяются данными Windows.
- Предупреждение 70 °C / порог выключения 75 °C сохранены; принудительное выключение может потерять несохранённые данные и не гарантировано при зависании Windows или источника датчиков.
- Проверены синтетические данные и Windows PowerShell 5.1 CI. Настоящий нагрев до порога не проводился.

## Обновление
В Git Bash в локальной папке 015_uTempGuard:
1. powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./Manage.ps1 -Action Stop
2. git pull --ff-only origin main
3. powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./Manage.ps1 -Action Start
4. powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./Emergency-Control.ps1 -Action Status

После обновления меню проверить вручную; если выбран новый режим «ВЫКЛЮЧАТЬ ПК ПО ТЕМПЕРАТУРЕ», обязательно отдельно подтвердить его в меню.
