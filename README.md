# uTempGuard 0.1.0

Локальный монитор температуры CPU для Windows 10 и Windows PowerShell 5.1. На этом ПК установлен **режим наблюдения**: предупреждения и журнал работают, закрытие приложений и выключение отключены.

## Что настроено

- CPU: Intel Xeon E5-2680 v4, 14 ядер / 28 логических процессоров.
- Источник: установленная AIDA64 Extreme 6.70, подписанная FinalWire. Драйверы/новое ПО этим проектом не устанавливались.
- Датчик: `TCPUPKG`, английская метка `CPU Package`, экспорт в `HKCU\Software\FinalWire\AIDA64\SensorValues`.
- Экспорт AIDA64 включён пользователем через настройки. `STIME` и `SDATE` используются для контроля свежести.
- uTempGuard стартует без повышения прав через ярлык текущего пользователя в папке Startup.
- С отдельного разрешения пользователя создана повышенная задача `uTempGuard-AIDA64-user`: запускает AIDA64 при входе этого пользователя. Пароль не сохраняется.
- Индикатор: отдельное окно WinForms в правом верхнем углу, `TopMost`, плюс значок в трее. Правой кнопкой доступна остановка.


## Компактный температурный индикатор (обновление интерфейса)

После установки обновлённой версии по умолчанию показывается небольшой текст `CPU 41°C` без фоновой панели вместо большой двухстрочной панели. При недостоверном датчике вместо температуры отображается `CPU --°C`; защитные разрешения от этого не меняются.

Правый щелчок по значку uTempGuard возле часов Windows открывает настройки: компактный/полный вид, размер текста, фон, непрозрачность 60/80/100%, четыре угла экрана, показать/скрыть индикатор и остановить монитор. Правый щелчок по самому индикатору открывает то же меню. Настройки сохраняются в `%LOCALAPPDATA%\uTempGuard\overlay.json` (не в `config.json`). Для изменений внешнего вида перезапуск не требуется. Значок трея работает даже при скрытой панели.

**Визуальный предпросмотр без реальных датчиков:** после обновления отдельной тестовой папки `015_uTempGuard_preview` запусти:

```bash
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File "../015_uTempGuard_preview/tests/Preview-Overlay.ps1"
```

Показывается постоянное **синтетическое** значение `CPU 41°C`. Окно не закрывается по исчерпании тестового сценария. Через правую кнопку на значке возле часов можно проверять все настройки и выбрать «Закрыть предпросмотр». Тест не использует AIDA64, основную конфигурацию, защитные действия или установленный монитор. Файлы интерфейса предпросмотра сохраняются в `artifacts/visual-preview-ui`, отдельно от реального `%LOCALAPPDATA%`.

Отдельная проверка недостоверного датчика: добавь параметр `-SensorFault`, чтобы увидеть `CPU --°C`.

**Проверка обновления:** изменения подготовлены в отдельной ветке, прежде чем применять их к работающему монитору, необходимы проверки на Windows PowerShell 5.1 и ручная проверка окна на этом ПК. Скрипт обновления предназначен только для одобренного `main` и сам не переводит защиту в Live.

После принятия PR и появления новой версии в `main` из каталога проекта запусти в Windows PowerShell:

```powershell
.\Update-uTempGuard.ps1 -Action Preview
.\Update-uTempGuard.ps1 -Action Apply
```

Скрипт сверяет origin, ветку и чистоту Git, обновляет только fast-forward, запрашивает подтверждение `UPDATE` и при необходимости штатно останавливает и запускает монитор. Никаких административных прав и доступа к чужим репозиториям не требует. При первом обновлении, когда файла Update-uTempGuard.ps1 ещё нет на ПК, сначала вручную получить его через Git после принятия PR.

Проверка настроек в песочнице без датчиков, запуска приложения или защитных действий:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\Test-Overlay.ps1
```

## Управление

Откройте `Управление.cmd`: меню статуса, запуска/остановки, конфигурации, журналов, диагностики и автозапуска. `Start-uTempGuard.cmd` запускает монитор скрыто, без консоли.

Команды из каталога проекта (Windows PowerShell):

```powershell
.\Install.ps1                     # установка/повторная установка и запуск
.\Manage.ps1 -Action Status
.\Manage.ps1 -Action Stop
.\Manage.ps1 -Action Start
.\Manage.ps1 -Action OpenConfig
.\Manage.ps1 -Action OpenLogs
.\Manage.ps1 -Action Diagnose     # шесть чтений за примерно 10 секунд
.\Manage.ps1 -Action DisableStartup
.\Manage.ps1 -Action EnableStartup
.\Uninstall.ps1                   # отключить автозапуск uTempGuard, остановить; сохранить данные
```

Изменения `config.json` применяются после остановки и запуска. `Mode=Observe` оставлять до отдельного подтверждения. `AllowList=[]`: ни одно приложение не согласовано на закрытие.

## Пороги и действия

| Условие | Намерение движка | Сейчас, Observe |
|---|---|---|
| ниже 70 °C, ранее не было Warning | обычная работа | индикация и журнал |
| от 70 °C | предупреждение, выбор разрешённых приложений с CPU строго >30% | только предупреждение и запись намерения |
| 69–69,999 °C после Warning | сохранить защитное состояние | только наблюдение |
| ниже 69 °C | прекратить защитное закрытие приложений | обычное состояние |
| от 75 °C | штатное выключение Windows | только запись намерения |
| нет датчика/неверные данные/нет свежего времени | SensorFault, действий нет | предупреждение и журнал |

Первое чтение после запуска намеренно недостоверно до изменения heartbeat. Максимальный возраст — 10 секунд; опрос — 2 секунды. Ошибка не сохраняет старую температуру как текущую. Температура вне `(0;110] °C`, NaN, отсутствие/дублирование выбранного ID и неверное время отвергаются.

Загрузка CPU: `100 × ΔCPU_seconds / (Δwall_seconds × число_логических_CPU)`. На этом ПК знаменатель учитывает все 28 потоков; один полностью занятый поток — около 3,57%. Используется фактическое `[Environment]::ProcessorCount`, а не зашитое 28.

## Защита приложений и боевой режим

Разрешённый список сейчас пуст. В будущем каждая запись требует точный полный путь `.exe`, SHA-256 и `Approved: true`, предварительно согласованные с человеком. Системные каталоги, оболочка, службы, процессы безопасности, неизвестный владелец, другой пользователь/сеанс и приложения без окна исключаются. Перед запросом закрытия повторно проверяются датчик, владелец, PID+время запуска, путь и хеш.

В коде предусмотрен только `CloseMainWindow()`: без Kill/Stop-Process и без эскалации после отказа. Приложение может запросить сохранение или отказать; снижение нагрузки не гарантируется.

Для реальных действий одновременно нужны `Mode=Live`, отдельные флаги действий и отсутствующий сейчас `live-approval.json` с явным подтверждением и SHA-256 конкретного конфига. Любое изменение конфига аннулирует такой допуск. Файл допуска в этой сессии не создавался. Имитация всегда блокирует выполнение независимо от режима. Не создавайте допуск до отдельного согласования, проверки списка приложений и готовности выключения.

Штатное выключение предусмотрено через `Win32Shutdown(1)`: без force-флага. Оно намеренно не испытывалось. Права на выключение, реакция программ и сохранение данных в этом сценарии пока не подтверждены. Это не аппаратная аварийная защита.

Журнал пишется в файлы. Источник Windows Event Log не регистрировался: для этого не потребовалось дополнительное повышение прав. В журнал не копируется весь экспорт AIDA64.

## Автозапуск AIDA64 и удаление

`AidaAutostart.ps1 -Action Status` читает задачу. Для `Install`/`Remove` нужен согласованный повышенный сеанс. Удаление uTempGuard не удаляет AIDA64, её настройки, исходники или журналы. Повышенная задача AIDA64 сохраняется отдельно, потому что её удаление также административное действие:

```powershell
# Только после согласования административного действия, в повышенном PowerShell:
.\AidaAutostart.ps1 -Action Remove
```

Если AIDA64 не запустится, будет закрыта или экспорт перестанет обновляться, монитор покажет ошибку и запретит действия. Не перемещайте её исполняемый файл из Downloads без обновления config/задачи. Фактический вход в Windows после установки ещё не проверен; текущий запуск использовал тот же Launch.vbs, что ярлык Startup.

## Ограничения температуры и OSD

Intel указывает для E5-2680 v4 **TCASE 86 °C** — температуру крышки корпуса, а не CPU Package. Поэтому 70/75 °C оставлены предварительными консервативными пользовательскими порогами; это не паспортные пределы Package и не измеренный TjMax. [Intel ARK](https://www.intel.com/content/www/us/en/products/sku/91754/intel-xeon-processor-e52680-v4-35m-cache-2-40-ghz/specifications.html), [разъяснение AIDA64](https://forums.aida64.com/topic/3395-cpu-package/).

Heartbeat подтверждает обновление экспорта AIDA64; производитель не гарантирует отдельную аппаратную метку времени каждого измерения или атомарность всех значений. Реальную температуру контроллера независимо от AIDA64 не калибровали.

RTSS/MSI Afterburner не обнаружены в проверенных установках и процессах. Отдельное TopMost-окно не гарантирует показ в эксклюзивном fullscreen. После остановки Computer Use клавишей Esc визуальная проверка индикатора не продолжалась; игра не запускалась. Установка RTSS и проверка игрового OSD — отдельный следующий шаг.

Охлаждение CPU требует доработки со слов пользователя. BIOS, напряжения и частоты не менялись; стресс-тестов не было.

## Максимальная температура доступных ядер — только наблюдение

Новая возможность: показывать максимальную температуру среди CPU Package (`TCPUPKG`) и доступных `TCC-1-1` — `TCC-1-14` (14 каналов ядер) в компактном индикаторе `CPU MAX N°C`. В меню у часов отображаются отдельные каналы и статус их наличия. Если ядра ещё не экспортируются AIDA64, показывается только CPU Package; **отсутствующие значения не подставляются**. Проверка источника требует корректного AIDA heartbeat и совпадения выбранного Package с основным измерением. Не добавляется смешивание температуры CPU-сокета или материнской платы в максимум.

Для получения всех 14 ядер их значения нужно включить в экспорт AIDA64 вручную (после проверки фактических ID и корректного времени). Никакие параметры экспорта, BIOS, драйверы или права администратора автоматически не меняются.

**Безопасность:** максимум ядер используется *только для экрана*. `Get-GuardDecision`, пороги, текущие разрешения Live, список приложений и способы закрытия/выключения не меняются. Массовое завершение процессов, force-выключение и обещание реакции «в ту же секунду» не реализуются. До проверки охлаждения не следует запускать игры или стресс-нагрузку.

## Экспериментальная аварийная реакция — НЕ АКТИВИРОВАНА

В отдельной кандидатной ветке реализованы две **строго опциональные** настройки, недоступные по умолчанию:

- `AppCloseScope = "ApprovedInteractive"`: при предупреждении 70 °C программа пытается штатно закрыть **только** интерактивные приложения, заранее перечисленные пользователем в `AllowList` с полным путём, SHA-256 и `Approved = true`. Она не завершает неизвестные процессы, службы, Windows или другие сеансы. `CloseMainWindow()` может встретить диалог сохранения, и приложение может остаться открытым.
- `EnableForcedShutdown = true`: только в отдельно одобренном Live-режиме и при `EnableShutdown = true` допускает вызов штатной утилиты Windows `shutdown.exe` с аргументами `/s /f /t 0` при повторно подтверждённой температуре от 75 °C. Для этого в **локальном** файле допуска кроме исходных условий требуется отдельное булево поле `ForcedShutdownApproved = true` и точный SHA-256 конфигурации. Ни этот файл, ни настройка Live не создаются автоматически. Без отдельного допуска вызов /f блокируется.

Триггер опирается на максимальное подтверждённое значение доступных CPU Package / TCC каналов; пропавший или устаревший канал не может использоваться для действий. Частота опроса (по умолчанию 2 секунды), обработка Windows и время выключения исключают гарантию выключения «в ту же секунду».

**Предупреждение:** `/f` принудительно закрывает работающие программы без запроса сохранения и может привести к потере данных. Официальный справочник Microsoft: https://learn.microsoft.com/ru-ru/windows-server/administration/windows-commands/shutdown . Это не заменяет корректное охлаждение и независимую аппаратную термозащиту. Не пытайтесь проверять пороги нагреванием компьютера. Пока охлаждение не исправлено, избегайте нагрузок.

Ветка и PR — только предложение к рассмотрению, без установки на ПК. Для безопасных проверок используйте только имитацию или изолированные unit-тесты. Не включайте Live до отдельного принятия рисков, проверки экспортируемых датчиков AIDA и утверждения списка приложений.

## Запуск нового интерфейса и ручное включение аварийной защиты

Новые функции должны быть слиты в основную ветку и загружены в исходную папку `015_uTempGuard`. Если открыть `Manage.ps1` из старой ветки, снова запустится старое окно без меню настроек; отдельный Git worktree не устанавливает программу.

После `git pull --ff-only origin main` перезапускайте монитор штатно через `Manage.ps1 -Action Stop` и `-Action Start`. Настройки AIDA64, локальный `config.json` и данные в AppData не подлежат перезаписи Git.

**Состояние по умолчанию:** `Observe` — только измерение, сигналы и журнал. Наличие кода аварийной защиты не означает, что он включён. На локальном ПК включение проверяем отдельным скриптом:

```powershell
.\Emergency-Control.ps1 -Action Status  # только проверка
.\Emergency-Control.ps1 -Action Enable  # подтверждение риска, два чтения AIDA, 15 датчиков, локальный receipt, перезапуск
.\Emergency-Control.ps1 -Action Disable # отозвать допуск, вернуть Observe, перезапустить
```

`Enable` не запускает `shutdown` в момент настройки. Он требует здорового монитора, CPU Package и 14 корректных каналов ядер с живым heartbeat, проверяет, что температура ниже 70 °C, и запрашивает ввод фразы **ENABLE FORCE SHUTDOWN**. Только после этого он сохраняет отдельный локальный допуск и перезапускает монитор в Live. Никаких административных прав не запрашивает, но права Windows на shutdown зависят от политики компьютера.

**Важное ограничение:** `shutdown /s /f /t 0` не означает гарантированного выключения в течение одной секунды и может уничтожить несохранённые данные. При зависании Windows, AIDA64, драйвера или потере датчика программная защита может не сработать. Пока охлаждение не доведено до конца, не считать этот скрипт заменой аппаратной защиты.

При 70 °C запрос штатного закрытия распространяется **исключительно** на заранее явно одобренные приложения в `AllowList`. При пустом списке никого не закрывает. Принудительного «очистить диспетчер задач» нет: для системных и неизвестных процессов это небезопасно.

### Исправление согласованности AIDA64 CPU Registry

Если основной датчик исправен (`Healthy=True`), но список 15 CPU датчиков недоступен, это **не обязательно** означает отказ AIDA64: реестр может обновиться между двумя чтениями. Модуль проверяет совпадение подтверждённого времени и CPU Package, делает до трёх коротких попыток при временном несовпадении и возвращает диагностический код при `Read-GuardCpuTemperatureSummary -VerifiedSample $sample -Diagnostic`. Режим автоматических действий при этом не включается, все существующие ограничения остаются.

`Emergency-Control.ps1 -Action Enable` при повторном несовпадении выполняет новое чтение первичного датчика (не более четырёх попыток), а при отказе сообщает код причины или идентификаторы отсутствующих датчиков. **Не изменять пороги или режимы ради прохождения проверки.**


## Один настоящий перезапуск Windows для проверки искусственных 75 °C

В tests/Invoke-OneShotRestartTest.ps1 предусмотрена опция Preview: она передаёт синтетические 75 °C в Get-GuardDecision и показывает Critical/Shutdown. Она не вызывает выключение/перезагрузку, не меняет настройки и не нагревает ПК.

Опция RestartOnce применяется только вручную, с присутствием человека у компьютера, после сохранения документов. Требует активный монитор Live с аварийным допуском, проверяет 15 настоящих датчиков AIDA64, причём реальные температуры должны быть ниже 70 °C. Перед реальным действием необходимо набрать RESTART ONCE. Тест записывает одноразовую метку в LOCALAPPDATA/uTempGuard/supervised-restart-tests до запроса Restart-Computer без параметра Force. Повторный запуск с тем же TestId не приведёт к новому перезапуску. Тест никогда не добавляется в автозагрузку. Windows может задержать перезагрузку из-за несохранённых документов.

Тест не проверяет настоящий нагрев до 75 °C, не доказывает исполнение принудительной команды shutdown /s /f /t 0 и не обеспечивает 100%-ной надёжности. Намеренно разогревать CPU и создавать автоматические циклы перезагрузок запрещено. Основной аварийный режим не меняется и после теста не требует обратного переключения.
